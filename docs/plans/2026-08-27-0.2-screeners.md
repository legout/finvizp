# finvizp 0.2 Screeners Implementation Plan

> **For Hermes:** Execute on the `finvizp` Kanban board after the 0.1 audit. Use strict TDD, isolated worktrees, same-card review, and merge-before-completion.

**Goal:** Add typed screener/query registries, complete public pagination, signals, earnings screens, and registry drift tooling.

**Architecture:** One deep `screener` module validates immutable human-readable query models and encodes provider codes from checked-in registries. A pure table parser and schema assembler support named fixed views and deterministic custom views. Signals and earnings are projections over the same collector, not duplicate transports.

**Tech Stack:** Existing 0.1 foundation, lxml, PyArrow, pytest.
