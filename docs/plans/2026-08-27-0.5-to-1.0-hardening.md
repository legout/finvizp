# finvizp 0.5 to 1.0 Hardening Implementation Plan

> **For Hermes:** Execute after the 0.4 audit. This phase closes the frozen manifest; it does not add new product families or publish a release.

**Goal:** Prove complete frozen-public and `finvizfinance` capability parity, harden schemas/fixtures/access behavior, publish migration/reference documentation, and produce a release-readiness verdict for explicit human approval.

**Architecture:** No new broad abstraction is expected. The work is evidence-driven: close manifest gaps, validate every schema and fixture, run a bounded family smoke matrix, and document the Arrow-native replacement workflow.

**Tech Stack:** Full package, pytest, Ruff, ty, build/Twine, GitHub Actions, machine-readable manifest validation.

---

## Card 0.5-A: Frozen-surface and legacy parity audit

**Files:**
- Modify: `src/finvizp/capabilities.json`
- Modify: `tests/test_capabilities.py`
- Create: `docs/reference/capability-matrix.md`
- Create: `docs/how-to/migrate-from-finvizfinance.md`

**TDD/evidence steps:**

1. Convert the frozen inventory and every audited `finvizfinance` public method into a unique manifest assertion.
2. Test every `implemented` operation imports, has async/sync pairing where networked, names an output kind/schema, and points to existing fixtures/tests/docs.
3. Test no `planned`, guessed, login-only, or Elite-only entry is exported as a public always-failing stub.
4. Map legacy capabilities to new operations or explicit Arrow replacement workflows; document intentional signature/type differences.
5. Include Arrow-native CSV/Excel examples using caller tools, without adding pandas or exporter dependencies.
6. Re-run the audited legacy inventory against pinned `finvizfinance` revision evidence; record changes, do not silently move the frozen goalpost.

**Commit:** `docs: complete public and legacy capability matrix`

## Card 0.5-B: Schema, parser, and fixture hardening

**Files:**
- Modify: `src/finvizp/schema_registry.json`
- Modify: parser/schema tests under `tests/`
- Create: `tests/test_fixture_hygiene.py`
- Create: `docs/reference/schema-versioning.md`

**TDD/evidence steps:**

1. Validate every table operation returns its registered schema for complete, partial, and empty results.
2. Test stable semantic names, types, units, nullability, raw companions, keys, and temporal semantics across all families.
3. Add cross-family normalization cases for compact values, fractions, dates, relative times, sentinels, and extra fields.
4. Add fixture hygiene tests rejecting cookies, authorization, account/portfolio data, tracking identifiers, oversized irrelevant content, and unsanitized proxy URLs.
5. Verify current and only justified recent structural variants; remove obsolete fixture branches rather than accumulating parser archaeology.
6. Generate/review schema reference docs from the registry or validate hand-written docs against it.

**Commit:** `test: harden schemas parsers and fixtures`

## Card 0.5-C: Public live matrix and operational docs

**Files:**
- Create: `.github/workflows/live-public.yml`
- Consolidate/modify: `tests/live/`
- Create: `docs/how-to/live-smokes-and-drift.md`
- Create: `docs/how-to/caller-owned-history.md`
- Create: `docs/explanation/access-and-responsible-use.md`

**TDD/evidence steps:**

1. Build one bounded sequential smoke per public family with conservative timeout/rate and no broad ticker/publisher/fund/manager/release traversal.
2. Categorize failures as network/access, entitlement/block/challenge, parser drift, data conversion, or assertion; do not collapse them into one red build.
3. Add a weekly non-PR-gating workflow with least permissions, no secrets, concurrency guard, artifact/report retention, and no telemetry.
4. Document explicit live invocation, expected variability, fixture refresh/scrub workflow, proxy/auth boundaries, and responsible-use limits.
5. Document provider history versus collector-built snapshots and caller-owned Arrow/Parquet persistence without adding storage helpers.
6. Verify default CI remains hermetic and unaffected by network availability.

**Commit:** `ci: add bounded weekly public drift matrix`

## Card 0.5-D: 0.5 milestone audit

**Assignee:** reviewer

**Acceptance:** Every frozen capability is `implemented` or explicitly gated with a justified non-public access classification; no public 1.0 requirement remains `planned`; all schemas/fixtures/docs/tests resolve; default CI is hermetic and Python 3.11–3.14 green; weekly live workflow is conservative and non-gating; migration guide covers all legacy methods; no new family or compatibility shim slipped in. Findings become focused remediation cards. Complete only after merged `main` and CI are green.

## Card 1.0-A: Stable release-readiness audit

**Depends on:** Card 0.5-D merged.

**Assignee:** reviewer

**No implementation or publication authority.** This card produces a verdict and, if needed, remediation cards.

**Checklist:**

1. Run `uv lock --check`, Python 3.11–3.14 tests, Ruff format/check, ty, docs checker, build, Twine check, secret scan, and `git diff --check` on clean `main`.
2. Verify wheel/sdist contents, package metadata, public exports, versions, and generated/reference schema consistency.
3. Verify all manifest entries, docs links, access tiers, operation imports, fixtures, and tests.
4. Run the bounded live matrix once and classify current drift; never bypass block/challenge/entitlement.
5. Review security: arbitrary URL prevention, query validation, redaction, proxy/auth isolation, retry/failover policy, fixture scrub, no telemetry/logging.
6. Review public semantics: strict/partial/empty, cancellation, ordering/dedupe, cache provenance, temporal honesty, and no crawler/persistence claims.
7. Confirm GitHub CI/security settings and tag-triggered trusted-publishing workflow remain configured but unused.
8. Produce one verdict: `READY_FOR_EXPLICIT_RELEASE_APPROVAL` or `NOT_READY` with focused blocking cards.

The reviewer must not bump/tag, create a GitHub release, or publish to PyPI. Those actions require a separate user-approved release task after this audit.
